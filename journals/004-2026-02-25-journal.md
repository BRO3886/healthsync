## What Changed

- **`internal/skills/skills.go`** — new package: `AgentTarget`, `DefaultTargets`, `Install`, `Uninstall`, `IsInstalled`, `InstalledVersion`, `DetectAgents`, `DisplayPath`, `SkillDir` — ported from `cal/internal/skills/skills.go`, s/ical-cli/healthsync/, s/.ical-version/.healthsync-version/
- **`cmd/skills.go`** — `skills install/uninstall/status` cobra commands with `--agent claude|codex|all` flag; interactive `huh.MultiSelect` picker when TTY; auto-detect when non-TTY
- **`internal/skills/skills_test.go`** — 8 tests: DefaultTargets, SkillDir, Install+Uninstall round-trip, idempotent reinstall, IsInstalled false when missing, InstalledVersion empty, DetectAgents, DisplayPath
- **`.claude/commands/release.md`** — copied from cal, adapted for healthsync (6-platform binaries, correct URLs, correct module path)

## Key Insights

### go:embed path constraint is the critical gotcha
`//go:embed` paths are relative to the source file and **cannot contain `..`**. Healthsync's root is `package main`, so a root-level `skills.go` with `package healthsync` would cause a package conflict. Cal avoids this because its root package is `package ical` (not `main`) — `main.go` lives in `cmd/ical/`.

**Solution**: Move skills dir into `cmd/skills/` so `cmd/skills_embed.go` (package cmd) can embed `skills/healthsync` with a relative path. Old root `skills/` dir removed.

### `Version` var is accessible in skills.go
`cmd/skills.go` uses `Version` (set via ldflags in `version.go`) directly — both are in `package cmd`. No need to pass it through function params.

### cal pattern is directly portable
cal's `internal/skills/skills.go` is completely generic — only the constants `skillDirName` and `versionFileName` need changing. The rest (WalkDir, WriteFile, RemoveAll, version tracking) is identical.

### huh form pre-selection pattern
```go
selected := preselected  // set before form.Run()
form := huh.NewForm(...huh.NewMultiSelect[string]().Value(&selected)...)
// selected is already set; form.Run() lets user modify it
```
The form mutates `selected` in-place. Pre-setting it before `Run()` gives the desired pre-checked state.

## Decisions Made

- **Moved `skills/` to `cmd/skills/`** instead of creating a new package (e.g. `internal/embedded/`) — keeps the cmd package self-contained, avoids an extra package just for embedding
- **No `skills_test.go` for cmd layer** — the `cmd/skills.go` file drives IO/TTY interactions; tested the pure logic in `internal/skills` with `testing/fstest.MapFS` instead
- **`testing/fstest.MapFS`** used in tests as a fake embedded FS — avoids needing real files on disk for the Install logic tests
- **Re-installed to `~/.claude/skills/healthsync`** after smoke-test uninstall — skill is live for the current session

## Key Insights

### Two CSS fingerprinted files in `public/css/` after redesign
Hugo doesn't delete old fingerprinted CSS files on rebuild — only the HTML references the new hash. Safe to ignore; CI deploy replaces the full public dir.

### Step list gap trick
`background: var(--border)` on `ol` + `background: var(--bg-card)` on `li` + `gap: 1px` creates hairline separators between steps without explicit `border-bottom` per item.

### 2-col grid with 1px dividers
`display: grid; gap: 1px; background: var(--border)` on `.home-grid` + `background: var(--bg)` on each `.home-grid-item` achieves the ruled-grid look with no extra pseudo-elements.

### `cmd-prompt` / `cmd-comment` spans inside `<pre><code>`
Raw HTML in layout template (not markdown) — rendered directly by Hugo. `unsafe: true` in goldmark is irrelevant here.

### Dot-grid hero texture
```css
background-image: radial-gradient(circle, var(--border) 1px, transparent 1px);
background-size: 24px 24px;
opacity: 0.45;
```
Uses `--border` so it works in both themes without duplication.

## Decisions Made

- **IBM Plex over JetBrains Mono** (used in cal/rem) — IBM Plex Mono has a more clinical/scientific feel; pairs better with IBM Plex Sans. Clearly differentiates healthsync visually.
- **Emerald green accent** — health = vitality = green. Completely different from cal (red) and rem (blue). `#00d68f` has good contrast on both dark and light surfaces.
- **Warm paper light mode** `#f8f6f1` — softer than cal/rem's near-white `#fbfbfd`.
- **No frosted glass nav** — cal and rem both use `backdrop-filter: blur`. Solid border-bottom is distinct and cleaner.
- **Numbered section headers (01–05)** — editorial feel; anchors content without heavy dividers.
- **`hs-accent` span on "health" in h1** — green "health" + default "sync" makes brand distinctive at a glance.

## Session 4 - 2026-02-25 - Website second pass: revert to clean minimal Apple blue

## Goal

User rejected Session 3 design — too much decorative chrome (dot-grid, glow bleeds, numbered sections, terminal wrapper, left-border accent strips on pre blocks). Rethink from scratch: genuinely clean and minimal, Apple blue, larger fonts.

## What Changed

- **`website/assets/css/main.css`** — complete rewrite (288 ins / 727 del):
  - Fonts: back to system stack `-apple-system / SF Pro` (removed Google Fonts `@import`, removed head.html preload)
  - Accent: restored Apple blue `#007AFF` / `#0A84FF` dark
  - Base font: **17px** (up from 15px); all body copy, labels, badges scaled up proportionally
  - Frosted glass nav restored: `backdrop-filter: saturate(180%) blur(20px)`
  - Hero: `2.75rem` h1, `1.12rem` desc, **pill-shaped** CTA buttons (`border-radius: 980px`)
  - Code block: plain `border-radius: 12px`, `border: 1px solid var(--border)` — no accent border strip
  - `.feature-list` — `border-bottom` row list, no bullets, `strong` label + description inline
  - `.install-block` — plain label (`display: block`) above each `pre`, no left-border cards
  - Quick start `ol` — CSS `counter()` circles (`counter-reset: steps`, `::before` with accent-subtle bg + blue numeral), `step-body` flex column div wrapping content
  - `.agent-questions` — subtle `bg-secondary` pill rows, `font-style: italic`, `::before` suppressed via `!important`
  - Removed: dot-grid, glow pseudo-elements, `--accent-glow`, `--accent-bright`, numbered section headers, terminal chrome classes, `home-grid`, `install-method` border-left, `agent-callout`, `home-eyebrow`, `cmd-prompt/comment`, `hs-accent`, IBM Plex, emerald green, warm paper bg

- **`website/layouts/index.html`** — simplified to single `.home > .container` flow:
  - Hero: plain `h1`, `home-desc`, `home-links`, `home-metrics`
  - Code block: `<pre class="home-code">` inline after hero, no wrapper div
  - Each section: `<div class="home-section">` with `<h2>` + content, no section-num spans
  - Feature list uses `<ul class="feature-list">` with `<strong>` + text inline
  - Install: `<div class="install-block">` with `<span class="install-block-label">` + `<pre>`
  - Quick start: bare `<ol>` items with `<div class="step-body">` inside each `<li>`
  - Agent questions: `<ul class="agent-questions">` with `<li>` italic strings

## Key Insights

### What failed in Session 3 (from user feedback)
- **Left 3px accent border on `pre` blocks** — looked busy, not clean
- **Separate terminal wrapper section** — broke the page flow; terminal chrome felt decorative not functional
- **Dot-grid + glow bleed** — too much visual noise for a "clean Apple-like" aesthetic
- **Numbered section headers (01–05)** — editorial device that clashed with the simplicity goal
- **IBM Plex + emerald green** — too distinctive/aggressive; user explicitly wanted Apple blue back

### CSS counter for ordered steps (no extra HTML)
```css
.home-section ol { counter-reset: steps; }
.home-section ol > li { counter-increment: steps; }
.home-section ol > li::before {
  content: counter(steps);
  min-width: 28px; height: 28px;
  border-radius: 50%;
  background: var(--accent-subtle);
  color: var(--accent);
  font-size: 0.82rem; font-weight: 700;
}
```
`step-body` div inside `<li>` wraps the actual content so flexbox doesn't break with `::before`.

### `.agent-questions li::before { display: none !important; }`
`.home-section ul li::before` rule added a `›` pseudo-bullet. `agent-questions` nested inside `.home-section` inherited it. Override with `display: none !important` — the `!important` is needed because the parent selector has equal specificity.

### Pill buttons match Apple HIG
`border-radius: 980px` on `.home-links a` produces Apple's "pill" button shape regardless of button size — a large radius that always exceeds half the height.

## Decisions Made

- **System fonts restored** — no Google Fonts. `-apple-system` renders as SF Pro on Apple devices, matching the native iOS/macOS Health app aesthetic. No FOUT, no external dependency.
- **No decorative chrome on code blocks** — just `border: 1px solid var(--border)` + `border-radius`. Lets the content speak.
- **Feature list as `border-bottom` rows** — mimics Apple's specs/comparison tables; scannable without card borders.
- **Kept metric badges** — they're genuinely useful content (shows what data is available), not decoration.

## Key Insights

### Hugo minifier strips `class="..."` quotes but keeps values
`grep 'class="t-cmd"'` returns nothing on the built HTML — minifier collapses to `class=t-cmd` (no quotes for single-class elements). Verifying with `grep -o "t-cmd\|t-border"` (no quotes) correctly finds the classes.

### Always-dark terminal: hardcode colours, don't use CSS vars
`.home-terminal` uses hardcoded hex values (`#1a1b1e`, `#242527`) instead of `var(--bg-code)` etc. This ensures the terminal stays dark even in light mode — which is the correct visual expectation for a terminal window.

### Span-annotated `<pre>` in Hugo layout (not markdown)
Spans inside `<pre><code>` in a layout `.html` file render as raw HTML — no escaping, no goldmark processing. Works cleanly. Would NOT work the same way in markdown content files (would need `unsafe: true` + raw HTML blocks).

## Decisions Made

- **Catppuccin Mocha palette** — well-known terminal colour scheme, good contrast, recognisable to developers. Pink for heart rate values is a meaningful semantic choice (matches iOS Health heart icon colour).
- **Always-dark terminal** — makes the widget visually distinct from the rest of the page in both light and dark modes; sets it apart as a "real terminal" not just a styled code block.
- **`.t-border` for box-drawing characters** — dimming `┌─┬─┐│` lines draws attention to the data inside the table rather than the frame.
