# Journal Entry 001 - 2026-02-12 - Initial implementation

## Goal

Build the entire healthsync CLI & server from scratch: streaming Apple Health XML parser, SQLite storage, CLI commands (parse/query/server), HTTP upload server, and unit tests.

## What Changed

- Scaffolded full project structure: `cmd/`, `internal/{parser,storage,server}`
- `internal/storage/sqlite.go` — DB init, WAL mode, schema migration (6 tables + indexes), batch insert with `INSERT OR IGNORE`
- `internal/storage/queries.go` — generic query with date filters, CLI-friendly table name aliases
- `internal/parser/types.go` — Record/Workout structs, target type map, per-table column definitions
- `internal/parser/xml.go` — streaming XML parser with `io.Pipe`-based DTD stripping, zip support
- `cmd/root.go` — cobra root with `--db` flag
- `cmd/parse.go` — parse command with `-v` verbose logging (rate, elapsed, periodic progress)
- `cmd/query.go` — query command with `--from/--to/--limit/--format` (table/json/csv)
- `cmd/server.go` + `internal/server/` — chi HTTP server with async upload parsing
- 53 unit tests across storage (29), parser (17), server (17)
- `.gitignore`, MIT LICENSE, README.md, claude commands

## Key Insights

### DTD stripping requires io.Pipe, not bufio.Scanner + MultiReader
**FAILED first**: Used `bufio.Scanner` to strip DTD lines then `io.MultiReader(&buf, r)` to rejoin. Scanner's internal buffering consumed bytes beyond what was scanned, leaving a gap. Fix: `io.Pipe` with a goroutine writing filtered lines — no bytes lost.

### xml.Decoder.Skip() on root element kills everything
**FAILED second**: Default case in token loop called `decoder.Skip()` which, when hitting `<HealthData>` (the root element), skipped the entire document. Fix: explicitly don't skip `HealthData` — only skip leaf elements.

### Sleep table has no `unit` column
**FAILED third**: `RecordColumns()` returned `unit` for all tables. Sleep is `HKCategoryType`, not `HKQuantityType` — no unit attribute. Fix: conditional column list in `RecordColumns("sleep")`.

### Async upload is essential for large files
User flagged that blocking the HTTP response during a 30s+ parse is bad. Switched to `202 Accepted` + background goroutine + `/api/upload/status` poll endpoint with `sync/atomic` counters.

### Real SQLite > mocks for testing
Temp dir SQLite runs in ~2s for 53 tests. No value in mocking `*sql.DB` for this project.

## Decisions Made

- **Pure Go SQLite** (`modernc.org/sqlite`) — no CGO, easier cross-compilation
- **Separate tables per metric** — cleaner than one big table with type column, allows different schemas (sleep has no unit, workouts have distance/energy)
- **`INSERT OR IGNORE` dedup** — UNIQUE constraints on `(source_name, start_date, end_date, value)`, idempotent re-imports
- **Batch size 1000** — good tradeoff for SQLite transaction overhead
- **Async upload** — `POST /api/upload` returns 202, parse runs in goroutine, poll status via GET
- **Conventional commits** — adopted for this repo

## Session 3 - Replace Doks theme with custom minimal Hugo site

### Goal

Replace the Thulite Doks theme (npm-based, ~180MB node_modules, broken styling) with a self-contained custom Hugo theme. Then tone down the marketing-heavy homepage to feel dev-made.

### What Changed

- **Deleted**: All Doks dependencies — `package.json`, `package-lock.json`, `node_modules/`, `config/_default/module.toml`, `params.toml`, `languages.toml`, `config/production/`, `config/next/`, `postcss.config.js`, `babel.config.js`, `.prettierrc.yaml`, `hugo_stats.json`, old `layouts/`, `assets/scss/`, `assets/js/`
- **Created custom theme from scratch**:
  - `hugo.toml` — single consolidated config (markup, menus, site settings)
  - `layouts/_default/baseof.html` — base template with dark mode, nav, footer
  - `layouts/_default/single.html` — three-column docs layout (sidebar + content + TOC)
  - `layouts/_default/list.html` — section index with linked cards
  - `layouts/index.html` — homepage (rewritten twice, see below)
  - `layouts/partials/` — head, nav, sidebar, toc, footer, dark-mode (6 partials)
  - `assets/css/main.css` — single CSS file, no SCSS, processed via Hugo Pipes
  - `static/js/main.js` — dark mode toggle + mobile sidebar (no animations)
- **Stripped `seo:` blocks** from all 8 content frontmatter files
- **Renamed `docs/` → `website/`**
- **Updated Makefile** — `docs`/`docs-dev` → `website`/`website-dev`, uses `hugo` directly

### Key Insights

#### Hugo hangs with `config/_default/` directory structure
**FAILED**: Initially kept the Doks-style `config/_default/hugo.toml` + `markup.toml` + `menus.toml` split config. Hugo hung indefinitely after "syncing static files" — no error, just stalled. The `rem/website` project (which works fine) uses a single `config.yaml` at root. Consolidating into a single `hugo.toml` at the site root fixed it instantly (35ms builds). Root cause unclear — possibly a Hugo bug with the config directory when no theme/module is configured, or stale `config/_default/` interacting badly.

#### First homepage was too flashy
First pass ported the Doks homepage content into the new theme: eyebrow tags, "Built for developers who own their data" marketing copy, colored icon badges on feature cards, pill buttons, staggered fade-in scroll animations, metrics "strip" with giant numbers. User correctly flagged this as too SaaS-landing-page. Rewrote to read like a README: monospace title, plain description, terminal code block, bullet list of features, numbered quickstart, and a simple technical summary table.

#### `noClasses = false` for syntax highlighting
Changed to `noClasses = true` (inline styles) to avoid needing a separate Chroma CSS file. Monokai style works out of the box.

### Decisions Made

- **Single `hugo.toml`** at site root instead of `config/_default/` directory — avoids Hugo hang
- **No npm, no SCSS, no build step** — plain CSS processed by Hugo Pipes (minify + fingerprint)
- **README-style homepage** — terminal code block as hero, bullet lists, plain `<table>` for architecture summary, no marketing language
- **No scroll animations** — removed IntersectionObserver, all content renders immediately
- **GitHub blue (`#0969da`)** as accent instead of Apple blue — fits the dev aesthetic
- **Monospace brand** in nav — `font-family: var(--font-mono)` on `.nav-brand`
- **Renamed `docs/` to `website/`** per user request
