# Journal Entry 005 - 2026-02-28 - db info command + update checker

## Goal

Two additions:
1. `healthsync db info` — CLI subcommand showing per-table row counts, last record date, DB file size
2. Auto skills install prompt in the curl install script (port from rem/cal pattern)
3. Background update checker with 24h cache (port from cal's `internal/update` package)

## What Changed

### `healthsync db info`
- `internal/storage/queries.go`: added `TableInfo`, `DBInfo` structs and `GetDBInfo(dbPath string) (*DBInfo, error)`
  - Queries `sqlite_master` for all user tables
  - Per table: `SELECT COUNT(*), MAX(start_date)` — skips 0-row tables
  - File size via `os.Stat(dbPath)`
  - Sorts by row count descending, sums total rows
- `cmd/db.go`: new file — `db` parent + `info` subcommand
  - go-pretty `StyleLight` table, same pattern as `query.go`
  - Columns: TABLE (underscore→hyphen), ROWS (comma-formatted), LAST RECORD (YYYY-MM-DD)
  - **Bug caught**: forgot `t.SetOutputMirror(os.Stdout)` — table rendered to nowhere silently, `fmt.Printf` header printed fine masking the issue

### Skills auto-install in curl script
- `scripts/install.sh` + `website/static/install`: appended after verify block:
```bash
echo ""
info "healthsync can install an AI agent skill..."
printf "Install agent skill now? [Y/n] "
read -r answer < /dev/tty 2>/dev/null || answer="n"
if [ "$answer" != "n" ] && [ "$answer" != "N" ]; then
    "${INSTALL_DIR}/${BINARY_NAME}" skills install || true
fi
```
- Both files must stay identical — Hugo serves `website/static/install` at `/install`

### Background update checker
- `internal/update/check.go`: full port from cal
  - Cache at `~/.cache/healthsync/update-check` (key=value format, 24h TTL)
  - `FetchLatestVersion`: GitHub releases API, 2s timeout, Accept: `application/vnd.github.v3+json`
  - `CompareVersions`: parses `v1.2.3` or `1.2.3`, strips pre-release suffix after `-`
  - `Check()`: cache-first, silently fails on network errors, writes cache on fresh fetch
- `internal/update/check_test.go`: 12 tests — ParseCache, WriteAndReadCache, IsCacheFresh, CompareVersions, FetchLatestVersion error cases, Check with fresh/stale/dev cache, CachePath
- `cmd/root.go`: wired into `PersistentPreRun` / `PersistentPostRun`
  - Background goroutine starts update check before command runs
  - Non-blocking `select { case result = <-updateResultCh: default: }` in PostRun — if goroutine didn't finish, notice silently skipped (shows next run via cache)
  - Also checks skills staleness: `InstalledVersion(t) != Version` → yellow warning to stderr
  - Skip conditions: `HEALTHSYNC_NO_UPDATE_CHECK` env var, `dev` build, `version`/`completion`/`skills` commands, non-TTY stdout

## Key Insights

- **go-pretty `SetOutputMirror` is required**: `table.NewWriter()` without `SetOutputMirror(os.Stdout)` silently discards output. `t.Render()` returns a string only if no output mirror is set — but we don't capture the return value, so output disappears. Easy to miss because surrounding `fmt.Printf` calls still work fine.
- **Update notice timing**: goroutine races against command execution. Most commands finish in <500ms; GitHub API usually <1s. Non-blocking collect means the notice occasionally misses on first run but always shows on subsequent runs (cache hit). This is intentional — never block the user.
- **Skills staleness check is local-only**: no HTTP, just `InstalledVersion()` reads `.healthsync-version` from the installed skill dir and compares against current binary version. Zero cost.
- **`sqlite_master` query for dynamic table list**: using `SELECT name FROM sqlite_master WHERE type='table' AND name NOT LIKE 'sqlite_%'` lets `db info` automatically pick up any future tables without code changes. No hardcoded list needed.

## Decisions Made

- **`db` as parent command**: future subcommands (`db vacuum`, `db migrate`, etc.) can hang off it cleanly. For now just `info`.
- **Table name display uses hyphen form**: `strings.ReplaceAll(ti.Name, "_", "-")` so output matches CLI table names (e.g. `heart-rate` not `heart_rate`).
- **No `--format` flag on `db info`**: stats output is human-facing only, not a scripting target. Plain text header + table is sufficient.
- **`HEALTHSYNC_NO_UPDATE_CHECK` skip condition**: same pattern as cal's `ICAL_NO_UPDATE_CHECK`. Lets CI/scripts suppress the check cleanly.
- **No `--output json` skip condition**: healthsync's query command uses `--format json` not `--output json`, so the cal pattern doesn't directly apply. Non-TTY stdout check already handles piped usage.

## Session 3 - 2026-02-28 - Expand skills schema reference with full DDL for all tables

## Goal

Update `cmd/skills/healthsync/references/schema.md` to include explicit DDL blocks for every table — previously only 6 tables had DDL (steps, blood_pressure, sleep, mindful_sessions, stand_hours, workouts); the other ~34 were only listed in a reference table without SQL.

## What Changed

- **`cmd/skills/healthsync/references/schema.md`**: complete rewrite
  - Added individual DDL blocks for all 43 tables, grouped by category
  - Categories: Cardiac/Vitals (9 tables), Activity/Energy (10), Body (4), Mobility/Walking (8), Running (5), Other (1), Category types (3), Workouts (1)
  - Each DDL block includes inline comments explaining the unit/semantic meaning of `value`
  - Added schema variant summary table at top (5-col standard, 4-col no-unit, 6-col blood_pressure, 10-col workouts)
  - Added 9 common query patterns at the bottom (steps daily total, HR weekly avg, blood pressure history, sleep duration, workout summary, VO2 trend, mindfulness minutes, HRV trend, body weight trend)
  - Preserved all existing content (blood pressure pairing note, sleep stage value table, stand_hours values)

## Key Insights

- The previous file was technically correct but agent-hostile: an agent couldn't see the actual column structure for `active_energy`, `basal_energy`, `body_mass`, etc. without inferring from the "standard 5-col schema" template. Explicit DDL per table removes that inference step.
- The go:embed in `cmd/skills_embed.go` picks up all files under `cmd/skills/healthsync/` — no code change needed, next `make build` will embed the updated schema automatically.
- Website `website/content/docs/schema.md` is a separate file (user-facing docs) and was not changed — it already uses a mixed approach (some explicit DDL, some grouped lists) which is fine for a human reader.

## Decisions Made

- **Individual DDL over grouped lists**: agents need exact column names and types, not "these tables share the standard schema." Worth the verbosity.
- **Inline value comments**: `-- count/min (BPM)`, `-- fraction (0.98 = 98%)`, `-- °C deviation from personal baseline` — gives the agent semantic context without requiring it to cross-reference another file.
- **Query patterns in schema ref**: added 9 SQL examples directly in the schema reference (not just the skill prompt) so an agent loading only this file gets both structure and usage patterns.
